# mode — مكتبة مودات الألعاب

موقع عربي باتجاه RTL لاستكشاف مودات الألعاب وإرسال إضافات جديدة لمراجعتها. تُحفظ بيانات الموقع في Turso، ولا تُعرض الإضافات إلا بعد اعتماد المسؤول. يمكن إرفاق ملف مصدر نصي أو ZIP محدود الحجم لمراجعة المسؤول؛ تُحفظ المرفقات خارج المسار العام ولا تُشغّل.

## المتطلبات

- Node.js 20 أو أحدث
- npm

## التشغيل محليًا

```powershell
npm install
npm run setup
npm run dev
```

ينشئ `npm run setup` سرًا لجلسات الدخول ويحفظه في `.env.local`. يمكن لأي عضو إنشاء حساب أو تسجيل الدخول بحساب Google موثّق. لا تشارك `.env.local`.

### إعداد Google OAuth

1. في [Google Cloud Console](https://console.cloud.google.com/)، أنشئ مشروعًا واعدّ شاشة موافقة OAuth. إذا كان التطبيق بوضع الاختبار، أضف `hi423179@gmail.com` ضمن المستخدمين التجريبيين.
2. أنشئ OAuth Client ID من النوع **Web application**، وأضف عنوان إعادة التوجيه المصرّح به:
   `http://localhost:3000/api/auth/callback/google`
3. انسخ Client ID وClient secret إلى `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` في `.env.local`. لا تضعهما في ملفات عامة أو تشاركهما.
4. أعد تشغيل `npm run dev`، ثم افتح `/login` واختر «المتابعة باستخدام Google».

يسجّل الموقع حساب العضو عند أول دخول ناجح، ويشترط البريد الموثّق من Google. يعرض الكتالوج إرسالات الأعضاء بعد مراجعتها واعتمادها. لا توجد مستوردات أو واجهات تنزيل آلية لمواقع المودات الخارجية؛ يمكن للمسؤول استضافة ملف يرفعه صاحب الإرسال يدويًا.

يمرّ التنزيل عبر `/api/download-url/[slug]`: يعيد الملف المستضاف أو رابط HTTPS مباشرًا، وإلا يعرض صفحة المصدر الرسمية. يتيح `/api/download/[slug]` تنزيل الملفات المستضافة مع استئناف `Range`. عند استضافة ملف يدويًا من صفحة المود، يُخزّن خارج المسار العام في `MOD_MIRROR_DIR` (افتراضيًا `./data/mod-mirrors`) ويُتاح تنزيله من الموقع.

### حجب ألعاب

قائمة الألعاب الممنوعة في `data/blocked-games.json` (حاليًا inZOI و The Sims 4). بعد تعديل القائمة:

```powershell
node scripts/remove-blocked-games.mjs          # معاينة ما سيُحذف
node scripts/remove-blocked-games.mjs --apply  # حذف السجلات وملفات الاستضافة
```

مفتاح Google Gemini المستخدم لتحليل الإرسالات منفصل عن بيانات OAuth المستخدمة لتسجيل الدخول؛ كلاهما إعدادان مختلفان حتى لو كانا من Google.


## الإدارة والعضوية

- دخول الأعضاء من `/login`، وصفحة الحساب من `/account`. لا يوجد رابط عام للوحة الإدارة.
- يظهر رابط لوحة المراجعة في صفحة الحساب للمسؤول وحده، ولا يظهر للأعضاء.
- يستطيع المسؤول حذف الإرسالات المعلّقة أو المودات المنشورة من لوحة المراجعة أو صفحة تفاصيل المود؛ يتطلب الحذف تأكيدًا نهائيًا.
- إرسال مود جديد يتطلب تسجيل دخول عضو، ويُربط الإرسال ببريده الموثّق.
- لوحة المراجعة على `/admin` لا تعمل إلا للحساب الإداري `hi423179@gmail.com`. بقية الأعضاء يُعادون إلى صفحة حساباتهم.
- صلاحية المسؤول مشتقة حصرًا من البريد الموثّق في إعداد Google؛ تسجيل الأعضاء لا يمنح صلاحية الإدارة.
- تحفظ بيانات العضوية (البريد والاسم والصورة وتاريخ آخر دخول) في قاعدة Turso.

قاعدة Turso مطلوبة لتشغيل الموقع؛ لا يوجد تخزين SQLite محلي بديل. لا تشارك رمز الاتصال.
يتضمن نموذج الإرسال وفلتر المكتبة نوع اللعبة (عالم مفتوح، مغامرات، RPG، محاكاة، استراتيجية، بقاء، وأكشن) منفصلًا عن تصنيف المود مثل الرسوميات والأدوات.

### إعداد Turso

1. أنشئ قاعدة بيانات في لوحة Turso، ثم انسخ عنوان الاتصال `libsql://...` من صفحة قاعدة البيانات.
2. أنشئ Database/Auth Token مخصصًا للتطبيق، ثم أضف القيم محليًا إلى `.env.local`:
   ```env
   TURSO_DATABASE_URL=libsql://اسم-قاعدتك-اسم-حسابك.turso.io
   TURSO_AUTH_TOKEN=ضع-الرمز-هنا
   ```
   احتفظ بالرمز سرًا ولا ترسله في المحادثة أو تضفه إلى ملفات المشروع.
3. إذا كانت لديك بيانات قديمة في `data/mods.sqlite`، أوقف الخادم وأضف المتغيرين ثم انقلها مرة واحدة قبل تشغيل الموقع على Turso:
   ```powershell
   npm run migrate:turso
   ```
   هذه أداة ترحيل اختيارية فقط؛ يرفض الأمر الكتابة إلى قاعدة Turso التي تحتوي سجلات تطبيق، ولا يغيّر قاعدة المصدر. بعد الترحيل لا يستخدم الموقع ملف SQLite.
4. شغّل `npm run dev`. تنشأ الجداول وتُملأ بيانات كتالوج المجتمع تلقائيًا. لا تشغّل الموقع حتى تضبط متغيري Turso.

## رفع الملفات وفحصها

- يمكن للعضو إرفاق ZIP أو ملف مصدر نصي مدعوم (مثل `.cs` و`.java` و`.js` و`.lua` و`.py` و`.ts` و`.xml`)، بحد أقصى 15 ميغابايت للرفع و1 ميغابايت لملف المصدر الواحد.
- ملفات ZIP تُفحص من دون استخراجها إلى القرص أو تشغيلها: حد أقصى 500 مدخل، و100 ميغابايت إجماليًا بعد فك الضغط، ونسبة ضغط 150:1 لكل ملف. تُرفض المسارات غير الآمنة والأرشيفات المشفرة وZIP64 والروابط الرمزية والأرشيفات المعطوبة؛ لا تُفتح الأرشيفات المتداخلة.
- الملفات المرفوعة تبقى خارج `public` في `data/mod-uploads`، أو في المسار المحدد بـ`MOD_UPLOAD_DIR`. هذه الحدود لا تضمن اكتشاف البرمجيات الخبيثة.
- تُحذف المرفقات بعد قرار المسؤول بقبول الإرسال أو رفضه.
- يتطلب إرسال مرفق موافقة صاحبه على إرسال نصوص المصدر إلى Google Gemini عند إجراء المسؤول للفحص. لا تُرسل الملفات الثنائية إلى Google. أنشئ مفتاح Gemini API من [Google AI Studio](https://aistudio.google.com/apikey)، ثم اضبط `GEMINI_API_KEY` محليًا في `.env.local`. يستخدم التطبيق Interactions API والنموذج الافتراضي `gemini-3.8-flash`، ويمكن تغييره عبر `GEMINI_REVIEW_MODEL`. لا تضع المفتاح في الشيفرة أو تشاركه، وأعد تشغيل الخادم بعد ضبطه.
- في لوحة `/admin` يظهر إجراء تحليل AI لكل إرسال، حتى لو لم يُرفق ملف (يحلل البيانات والوصف ورابط التنزيل فقط). عند إرفاق ملف، يحلل أيضًا المصدر النصي المسموح بعد الموافقة. يجب ضبط `GEMINI_API_KEY` في `.env.local` وإعادة تشغيل الخادم لتمكينه؛ تعرض اللوحة تنبيهًا وزرًا معطلًا حتى يُضبط المفتاح. عند تعذّر Gemini، تعرض اللوحة تنبيهًا وتحفظ نتيجة الفحص المحلي للملفات المرفقة. النتائج توصيات غير مضمونة؛ المسؤول وحده يقرر القبول أو الرفض.
- فحص الملفات محصور بعشر عمليات في الساعة للمسؤول، ولا يُشغّل شيفرة أو ملفات واردة. نصوص المصدر غير الموثوقة تُرسل فقط بعد طلب التحليل الصريح من المسؤول.

### إعداد Google Gemini (التحليل)

1. أنشئ مفتاحًا من [Google AI Studio](https://aistudio.google.com/apikey) وضعه في `.env.local` باسم `GEMINI_API_KEY`، ثم أعد تشغيل الخادم.
2. النموذج الأساسي من `GEMINI_REVIEW_MODEL` (الافتراضي `gemini-3.8-flash`)، ويمكن وضع عدة نماذج مفصولة بفواصل ليجربها التطبيق بالترتيب. إذا كان النموذج مشغولًا (HTTP 503) أو انتهت مهلته، ينتقل تلقائيًا إلى `GEMINI_FALLBACK_MODELS` (الافتراضي `gemini-3.6-flash,gemini-3.5-flash-lite`)، ثم يعيد دورة كاملة مرة واحدة خلال ميزانية زمنية محدودة.
3. عند نجاح التحليل يُعرض اسم النموذج المستخدم في نتيجة الفحص داخل لوحة `/admin`. وعند فشل جميع المحاولات تُحفظ نتيجة الفحص المحلي فقط ويظهر تنبيه يوضح السبب.
4. في الحصة المجانية من Google Gemini، لكل نموذج حد يومي للطلبات (مثلًا 20 طلبًا يوميًا لـ`gemini-3.8-flash`). عند بلوغه يتجاوز التطبيق النموذج المستنفد تلقائيًا ويتذكر المدة المتبقية، ويذكر في التنبيه وقت إتاحته بدل تكرار المحاولات.

## الفحوصات

```powershell
npm run typecheck
npm run test:security
npm run test:review
npm run test:mirror
npm run test:download
npm run build
```

تفرض الإرسالات روابط HTTPS، وتُطبّق ترويسات حماية للمتصفح. يُسمح لكل عضو بخمسة إرسالات خلال 15 دقيقة، مع تحديد حجم الطلب؛ حدّ المعدل محفوظ في ذاكرة عملية الخادم، لذا على النشر متعدد النسخ استخدام تحديد معدل مشترك على مستوى المنصة.

## تدفق الاستخدام

1. يرسل العضو بيانات المود ورابط تنزيل خارجيًا، ويمكنه إرفاق ملف مصدر أو ZIP.
2. تحفظ الإرسالات والمرفقات بحالة «قيد المراجعة» ولا تظهر في الكتالوج العام.
3. يسجل المسؤول دخوله من `/admin`، ويفحص المرفق اختياريًا، ثم يقرر القبول أو الرفض يدويًا.
4. المودات المقبولة فقط تظهر في نتائج البحث وصفحة التفاصيل.
